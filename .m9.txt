transport: ask the scope question everywhere, and stop leaking the credential

Five defects on the serving surface, four of them the same shape: the
decision about who may do what lived inside the request handler, where it
could only be observed through a socket.

LFS (#153). The route table ended its git arms and fell through to
`_ => None`, which the matcher reads as "no credential required". A server
with tokens configured served every stored asset and answered every lock
request to an anonymous caller, while the same repository over the JSON
routes refused it. `/info/lfs/` now requires Write: LFS downloads objects
and LFS locks are what stops two clients writing the same asset.

Bundle scope (#149). `POST /v1/bundle` checked the role and nothing else,
so a token scoped to one branch could push to any other. It takes the
grant now and asks `permits_branch` before the bundle is decoded, so a
refused push writes nothing rather than being undone afterwards.

Empty content entry (#152). An entry with empty content is the signal to
read the bytes off disk, and the path came from the request body: a client
could name `/etc/passwd`, have it stored as an object and read it back
through the ordinary file routes. A tree path is relative with no climbing
component; anything else is refused before a read, in the one function
that opens a file on the caller's word.

Leaked credential (#169). `route()` ended its auth chain in
`Box::leak(...)` to turn an owned `String` into a `&str`. A long-running
server grew by one decoded token per authenticated request, and the
plaintext stayed readable for the life of the process. A `String` binding
has the same lifetime and no leak.

`ApplyError` had no `Display`, so the sentence a `Rejected` carries could
not be read at all; a scope refusal reached the client as a generic error
while the explanation sat in the variant.

Also #217, #216 (this branch, earlier): `.gesta/auth` is written 0600 at
creation, and a token selector means one entry or a refusal.

Tests were checked red, not just green. The first LFS test asserted a
status of 400 or more and passed with the arm deleted, because a 404 for an
unrouted path also satisfies that; it now asks `required_role` directly.
Deleting the arm reports `left: None, right: Some(Write)`. Removing the
path guard reports `an absolute path was accepted: csb0c9f904f143`.

554 tests, fmt 0, clippy 0, 87/87 documented surfaces, 31/31 refusals over
128 commands.

Closes #149, closes #152, closes #153, closes #169, closes #216, closes #217.
